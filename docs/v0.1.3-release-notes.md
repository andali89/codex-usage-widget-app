# v0.1.3 — Compact widget sizing and countdown readability

**Unreleased.** This version is prepared locally; no v0.1.3 tag, installer or GitHub release has been created. Published download links still point to v0.1.2.

- Settings offers four independent remaining-time bar counts: Edge and HUD, each with 5-hour and weekly choices from 2–12 (default 10). Save applies them, Cancel restores them, and strip/widget widths stay fixed. Existing bar counts are preserved when configuration migrates to settings schema 12.
- Edge and HUD have independent whole-widget size controls from **80% to 300%** (default/reset 100%), plus shared bold and higher contrast reset-countdown switches (both default Off). These settings apply across themes and use temporary preview, Save and Cancel. Native monitor-fit limits reject oversized selections; saved enlargements temporarily fall back to 100% if the environment later becomes too small. See the [appearance report](widget-appearance-and-snap-implementation-report.md) for validation and remaining manual checks.
- The compiled main executable is now `Usage.exe` by default, including future portable and installed builds. The product name and version remain Codex Usage Widget 0.1.3.
- Screen Edge uses the selected A · Subtle reference profile: 46 px rings, 11.5 px percentage text and 11 px countdown text, while keeping its 54 px width. Revised top spacing and an extra 4 px below the bottom indicator are included. The segmented reset indicator is 42 px wide.
- The Edge warning icon sits lower within the existing bottom padding, clearing the quota graphics and retained-data outlines without resizing the widget.
- Compact HUD adds the selected 8 px gap before its warning icon. Only layouts with a warning grow by 8 px; quota content stays in place and height remains 38 px.
- npm, Cargo, Tauri, lockfiles and packaging-check defaults use version 0.1.3. Codex app-server client metadata now uses the Cargo package version.

The [layout implementation report](layout-polish-implementation-report.md) records the actual layout checks and builds. The [implementation report](implementation-report.md) records version preparation and compilation. Native pointer/focus, mixed-DPI and installation behavior still need manual validation for this version. Existing notification-delivery limitations and unsigned-build warnings continue to apply; see the [README limitations](../README.md#known-limitations).
