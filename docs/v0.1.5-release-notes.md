# v0.1.5 — Diagnostics and steadier quota checks

**Draft · Unreleased.** The development version advances from 0.1.3 to 0.1.5. No v0.1.5 tag, installer or GitHub release has been created; published downloads remain at v0.1.2. The account-notification correction below is implemented and tested in source; long-running live comparison remains outstanding.

A local **Windows x64 portable ZIP** was compiled on October 30 and its version, archive contents and hashes verified. It **predates the November 4 account-notification correction**. Build paths, checksums and validation limits are recorded in the [implementation report](implementation-report.md#local-portable-build--2026-10-30).

## Added: optional local diagnostics

- Enable diagnostic logging in **Settings → Connection & diagnostics**, Save, and use **Open logs folder** to access the recorded evidence. Logging is off by default.
- Record loading and stale episodes, refresh triggers, failures/timeouts, recovery, shared-state delivery, and webview lifecycle. Startup loading and loading after previously usable data can be investigated separately. Aggregated render counts help investigate UI activity without logging every render.
- Logs stay beside the active configuration in `diagnostics/`. Buffered, event-driven recording and rotation limit retained logs to **5 MiB per configuration folder**. Credentials, account identifiers, quota values and raw protocol responses are excluded.
- A local summary script reports episode frequency, duration statistics, incomplete observations, recurring errors and observed triggers. See the [diagnostic logging guide](diagnostic-logging-implementation-report.md) for collection, analysis and validation details.

## Fixed in source: account notifications no longer immediately empty the widget

- A late account notification now triggers one bounded recheck in the same Codex process. The affected response is discarded; a consistent replacement is published without first clearing validated values.
- Verified ordinary transport failures preserve values marked out of date. Confirmed account/workspace changes, sign-out and unresolved verification still hide old-account values and suspend bound reminders/reset checks.
- Overview, compact warnings and tray fallback distinguish active account verification, unresolved verification and waiting for retry. Repeated notifications cannot start an unbounded recheck loop.
- Synthetic protocol/service tests and isolated Windows checks cover the corrected transition, account isolation and pending/active/recovery presentation in Overview, Edge and HUD. The shared scheduler and missing-field confirmation policy remain in place.

The [account-update investigation and validation report](account-update-empty-quota-investigation.md) records the original and additional supplied logs, deterministic reproduction and correction. A long-running live post-fix comparison and real account/workspace change testing remain pending. Diagnostic logging alone does not change loading behavior.

## Carried forward and release readiness

The earlier [0.1.3 development changes](v0.1.3-release-notes.md), including compact widget sizing and countdown readability, remain included. npm, Cargo, Tauri, lockfiles and packaging-check defaults now identify version 0.1.5; dependency versions are unchanged.

Frontend/Rust checks and the corrected embedded-frontend debug executable's isolated Windows checks passed on November 4. The older portable ZIP has not been runtime-tested and contains no correction. The installed Tauri CLI binding issue, unresolved notification delivery, and existing manual Windows validation limits remain documented in the project reports and [README](../README.md#known-limitations). No replacement installer/portable archive or public release was created.
