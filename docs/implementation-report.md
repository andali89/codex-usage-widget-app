Known container fields with unusable types and invalid RPC envelopes fail compatibility validation; missing methods and invalid request/parameter RPC errors are classified separately from transient server errors, timeouts, process exits and authentication problems.

## Implemented architecture and decisions

### Approved dependency and packaging decision (2026-10-23)

Proposed project-local Rust dependencies are `tauri-plugin-single-instance =2.5.4`, `tauri-plugin-autostart =2.7.0`, and `tauri-plugin-notification =2.7.0`, as recorded in the official Tauri plugins workspace manifests on this date. Register single-instance handling before service creation; keep autostart disabled by default and expose requested/effective state; send ordinary notifications only from Rust after durable claims. No JavaScript plugin permissions, global installation, shell-profile changes, toast actions, or scheduled-after-quit delivery are proposed. Exact versions and their transitive dependencies will be locked and validated before use.

Packaging proposal: enable the existing NSIS target for a per-user installer, using Tauri's project-local/cache NSIS download, without installing global NSIS or WiX. Build and inspect the installer first; actual install/upgrade/uninstall testing remains a separate runtime action and must preserve existing user state. Unsigned local builds must be identified as unsigned. Installed notification identity must be validated before claiming notification acceptance.

The README and development-environment setup require user confirmation before additional plugins or installer tooling are installed. The user explicitly approved **plugins and NSIS tooling** on 2026-10-23. The three pinned plugins are downloaded and locked; approved NSIS 3.13 and helper 0.5.3 are downloaded in the Tauri per-user cache. This approval covers project-local dependencies and Tauri-managed packaging tools, without global tooling changes. Official source manifests: [single instance](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/single-instance/Cargo.toml), [autostart](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/autostart/Cargo.toml), [notification](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/notification/Cargo.toml).

`src-tauri/src/service.rs` serializes snapshots, refresh triggers and settings writes. A bounded channel carries commands; a single supervised worker returns a read tagged with its generation. React never connects to Codex or schedules usage reads. Frontend countdown timers stop when the document is hidden. `src/replica.ts` rejects older/duplicate snapshots and retired epochs; revision gaps request a full state.

`protocol.rs` permits only `initialize`, `initialized`, `account/read` and `account/rateLimits/read`. Unhandled server requests receive a read-only error. Frames are capped at 1 MiB before allocation; stderr is continuously discarded with a fixed buffer. Reads/initialization have 15-second deadlines. Native Windows children use `CREATE_NO_WINDOW`, kill-on-drop and a kill-on-close Job Object. Normal shutdown closes stdin and allows two seconds before termination. The overall multi-request cycle can exceed 15 seconds; the limit applies per request.
