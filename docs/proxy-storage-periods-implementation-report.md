# Proxy, configuration locations, and compact period controls

Implemented: 2026-10-24. This report distinguishes implementation from runtime evidence; the overall app remains a public preview.

## Connection and display behavior

Connection settings accept an optional HTTP/HTTPS proxy URL without authentication. Blank retains inherited network behavior. Rust validates the URL and supplies HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, WS_PROXY, WSS_PROXY and a loopback-only NO_PROXY value to its owned Codex app-server child. Upper/lowercase environment names are handled consistently. A selected proxy also adds process-only config overrides features.respect_system_proxy=false and features.system_proxy_fallback=false, keeping system/PAC routing from superseding the environment where those features are supported. No global environment, Windows proxy, persisted Codex configuration, credential file, TLS trust setting or frontend network capability is changed. The policy choice follows the [Codex 0.164 outbound-proxy implementation](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/http-client/src/outbound_proxy.rs); it does not add a version gate. Changing the proxy retires the old connection generation and reset observations, then retries a read. Network failures remain separate from protocol incompatibility warnings. Socks, authenticated proxies and PAC configuration are outside this increment.

Display settings independently select Both, 5-hour only or Weekly only for Screen Edge and Compact HUD. The selection filters the whole shell reading and its accessible summary, including bars/rings, labels and countdowns. Effective countdowns are the intersection of displayed periods and saved countdown switches. Hidden switches remain saved/checked but disabled in Settings. Hover previews, Overview, tray information, polling and reminder rules retain their full data. Unrecognized window durations remain available in details rather than being relabeled as 5-hour or weekly readings.

Single-period footprints at default text size are Edge 54 × 116 (Words) or 54 × 96 (Badges), plus 24 height per visible enabled countdown; HUD 120 × 38 (Words) or 102 × 38 (Badges), plus 64 width per visible enabled countdown. Both-period sizes remain unchanged. Warnings add their established spacing. Dimensions remain stable across normal readings and ticking countdowns. Missing percentages remain unavailable, not zero.

## Storage ownership and migration

Widget state defaults to state.json and state.backup.json beside the widget executable. General settings can select that directory, the existing per-user AppData directory, or an absolute custom folder using text entry or the native Windows folder chooser. The UI reports both preferred and effective folders. Auth files and Codex's own config are never moved; displayed quota snapshots are not restored from disk.

Settings schema 5 adds proxyUrl, storageLocation and per-mode visiblePeriods. Missing settings migrate to inherited network behavior, the EXE location preference and both visible periods. Envelope format 4 keeps settings and the entire opaque reminder ledger together and adds a stable storage profile ID and monotonic data revision covered by the checksum. Old schemas/envelopes migrate; newer formats remain protected from writes. Windows atomic replace now uses extended-length paths, with a long Unicode path regression test.

The location manifest is storage-location.json beside the widget EXE when writable. Otherwise it is stored under AppData/storage-locations using a hash of the normalized EXE directory. The newest valid revision among portable/fallback manifests and their backups wins; ties favor the portable manifest. State paths are normalized consistently before and after folder creation. Future locator formats in any primary or backup block all startup and relocation writes; a corrupt locator recovered from a valid backup is archived before repair and pauses reminders. Folder writers hold an exclusive state.lock lease. A busy writer is reported rather than forked into a second active profile.

Startup and runtime resolution use preferred folder → EXE folder → AppData, skipping duplicates. Existing AppData settings/history are copied to an empty writable EXE folder; original files remain. Existing portable data takes precedence over unrelated AppData data. A runtime fallback carries the latest in-memory settings and ledger together, retains the preferred selection and reports the effective location. On restart, accessible copies of the same profile are compared by data revision and the newest is restored to the preferred directory when available. When the last writer is unavailable and only an older copy can be recovered, reminders pause until explicit re-enablement with the existing silent-baseline rules. Corrupt/newer legacy sources cannot be silently replaced by a fresh default configuration.

A changed destination is inspected through a narrow native command returning a conflict flag and opaque fingerprint. Settings Save checks the fingerprint again under the destination writer lease. Existing data requires Use destination configuration, Copy current configuration, or Cancel. Invalid/unrelated/newer files are preserved. Copying retains dated previous primary and backup files. Loading a profile resets transient usage, account binding and old reset work, then establishes a fresh silent baseline.

Relocation writes a synced staged snapshot, atomically commits a locator journal, activates the snapshot with atomic replacement, then clears the journal and swaps the writer. Before journal commitment a staged file is ignored. After commitment, startup verifies hashes and rolls the move forward. Failed activation rolls the locator back; an unresolvable rollback blocks writes. Neither settings nor delivery claims report a successful save before the committed destination is usable.

The Windows folder picker uses additional features of the already pinned Windows bindings, with no dependency version changes or additional plugin/tool installation. Only the main dashboard receives the new choose-folder and inspect-location IPC permissions; no general filesystem or shell permission was added.
